# تقرير تنفيذ ميزة "مجلدات القضايا" (Case Folders)

## 1. ملخص التنفيذ
تم بنجاح الانتهاء من تنفيذ ميزة **مجلدات القضايا** وفقاً لجميع المتطلبات، مع مراعاة العزل التام بين الشركات (Tenant Isolation) وتطبيق قواعد الصلاحيات المطلوبة. تم إجراء التعديلات البرمجية الضرورية على مستوى قاعدة البيانات، وخوادم الـ API، وواجهة المستخدم، دون المساس بالمميزات الأساسية الأخرى للقضايا.

## 2. تصميم قاعدة البيانات
تمت إضافة:
- `CaseFolder` كنموذج (Model) جديد في `schema.prisma` و `schema.postgresql.prisma`.
- حقل `folderId` للنموذج `Matter` وهو حقل اختياري (Nullable).
- تم الاعتماد على `onDelete: SetNull` في العلاقة بين المجلد والقضية، مما يضمن عند حذف المجلد أن تُصبح قضاياه تلقائياً "بدون مجلد" بدلاً من الحذف المتسلسل (Cascade Delete).
- علاقات الربط بين `User` والمجلد بصفته `createdBy`، والمشاهدين `viewers`.

## 3. Migration
تم تشغيل أمر المزامنة `npx prisma db push` و `generate` لتطبيق تحديثات `schema` على قاعدة بيانات SQLite بنجاح.

## 4. APIs المضافة أو المعدلة
1. **`GET /api/lawyer/folders`**: يجلب المجلدات مع العزل بحسب `tenantId`. يتم إرجاع المجلدات للمستخدم إذا كان مدير نظام أو مدير مكتب، أو كان منشئ المجلد، أو أضيف كمشاهد للمجلد.
2. **`POST /api/lawyer/folders`**: إنشاء مجلد جديد مع قائمة مشاهدين.
3. **`PATCH /api/lawyer/folders/[id]`**: تعديل الاسم والمشاهدين.
4. **`DELETE /api/lawyer/folders/[id]`**: حذف المجلد بأمان.
5. **`PATCH /api/lawyer/matters/[id]/folder`**: تغيير مجلد قضية موجودة.
6. **`POST & GET /api/lawyer/matters`**: تم التعديل لدعم جلب الفلترة `folderId` وإسناده للقضية الجديدة.

## 5. الشاشات والمكونات المعدلة
- تحديث شامل للصفحة `app/(lawyer)/matters/page.tsx`:
  - إضافة شريط مجلدات أفقي يتيح الفلترة بضغطة زر.
  - إمكانية فتح مودال "إنشاء مجلد" ومودال "تعديل المجلد".
  - إضافة زر/قائمة لنقل القضايا في نافذة التعديل.
  - إضافة اختيار المجلد في نافذة "إنشاء قضية".

## 6. قواعد الصلاحيات
- **منشئ المجلد**: يرى المجلد تلقائياً، ويستطيع حذف أو تعديل المجلد وإضافة المشاهدين.
- **مدير النظام / مدير المكتب**: يستطيع رؤية **كل** المجلدات في شركته وإدارتها دون الحاجة لإضافته كمشاهد.
- **المستخدم العادي (غير المختار)**: لا يستطيع رؤية المجلد، ولا يصل إليه عبر الـ API.

## 7. طريقة عزل الشركات (Tenant Isolation)
- جميع الـ APIs تقوم بالتحقق من `session.tenantId` ومقارنته بالبيانات.
- عند إضافة قضية إلى مجلد، يتم التحقق من أن المجلد يعود لشركة المستخدم.
- لا تظهر مجلدات الشركات الأخرى في القائمة أو في الـ API.

## 8. نتائج الاختبارات (Build & Logic)
- **نتيجة الـ Build**: ناجحة `✓ Compiled successfully`.
- **حذف المجلد**: حذف المجلد آمن ولا يسبب فقدان القضايا (يعود الفضل في ذلك لـ SetNull في الـ schema).
- **وصول مدير النظام**: مضمن في الكود `isManager` والذي يمرر المدراء عبر طبقة فلترة المشاهدين.
- **عدم وصول غير المصرح له**: جميع استعلامات الـ database للمجلدات تعتمد إما على دور الإدارة أو الارتباط المباشر (كصانع للمجلد أو مشاهد).
